# 接口数据交互层研究报告（脱敏）

> 方法：只读探测（响应头/无效参数/频率/分页/UA/记录深度）+ 自动化日志证据
> 探测时间：2026-08-20 ｜ 探测方式：对只读接口发请求，无任何破坏性操作
> 适用目标：为自动化稳定性 & 桌宠游戏"服务端设计"提供依据

---

## 一、传输层

| 项 | 实测 | 含义 |
| --- | --- | --- |
| 协议 | HTTP/1.1 | 无 HTTP/2 头部；每个请求独立往返 |
| 服务器 | `Apache` | 老牌 WAP 架构（页面是 XHTML Mobile 1.0 + pgconvert.css） |
| 缓存 | `Cache-Control: no-cache` | 每次都是实时渲染，无边缘缓存 |
| Content-Type | `text/html` | 纯服务端渲染，无 JSON API |
| Set-Cookie | 无 | 会话凭证完全由客户端持有，服务器不刷新 |
| 单页大小 | index 24.7KB / 背包 9KB / 强化 16.7KB | 轻量页面 |

## 二、认证与校验（安全性观察）

| 校验项 | 是否校验 | 证据 |
| --- | --- | --- |
| Cookie | ✅ 唯一鉴权 | 无 cookie → 无状态/重定向 |
| User-Agent | ❌ 不校验 | 无 UA / curl UA 均正常返回（页面还略大 1.2KB，疑似按 UA 微调） |
| Referer | ❌ 不校验 | 客户端从不发 Referer，一切正常 |
| Origin / CSRF | ❌ 无防护 | **所有操作都是无 token 的 GET**，任何携带 cookie 的 GET 都能触发状态变更 |
| 参数校验 | 宽松 | 多余参数被忽略（`cmd=index&style=1;cat` 照常返回首页） |

**设计教训**：GET 即执行变更 = 无 CSRF 防护 + 重复请求风险。
幸运的是服务器对每日领取有"已领取"守卫（幂等），但**并非所有接口都幂等**（斗神塔爬塔、乐斗消耗体力不可重放）。

## 三、错误处理

- **"很抱歉，系统繁忙，请稍后再试!" 是通用错误页**（1071 字节）：无效 cmd、空 cmd、未知模块、以及真正的服务器繁忙都返回它
- 客户端无法通过错误信息区分"限流 / 参数错误 / 服务器故障"——这是逆向噪音，也是自动化重试策略要模糊处理的原因
- HTTP 状态码恒为 200：**没有 4xx/5xx 语义**，一切靠页面文本判断

## 四、频率限制

| 层面 | 实测/证据 | 结论 |
| --- | --- | --- |
| 页面级读请求 | 20 连发 cmd=index：**0 次拦截**，平均 617ms、最大 966ms | 读请求无硬限流，但**服务器延迟 ~600ms 本身就是天然限速器** |
| 动作级限流 | 日志证据："刷新过于频繁，请稍后再试"（镖行天下刷新） | **部分动作有独立限流**（如刷新类操作） |
| 自动化现状 | 并发 5 账号、单任务串行、0.2s 繁忙重试 | 远低于任何可疑阈值 |

**对自动化的建议**：保持现状节奏（单任务串行 + 并发 ≤5）；不要做并发放大或高频爆破；
斗神塔每层 ~12s 的耗时是服务器处理时间，不是限流，无需加速。

## 五、数据边界

| 项 | 实测 | 含义 |
| --- | --- | --- |
| 分页越界 | `page=999` → 静默回落到有效页（不报错） | 分页参数宽松，可安全探测页数（数到不变即到底） |
| 乐斗记录保留 | **仅当天，约 5 条** | 战报是**当日易失数据** → 快照必须当天抓（现有 22:00 任务正好覆盖） |
| 战报 URL | 包含用户 QQ 号（`id=<QQ>_8_...`） | URL 泄露用户标识（隐私设计缺陷） |
| 世界喇叭 | 用户名后 2 位打码（`24280883**`） | 部分场景有脱敏 |
| 背包 | 18 页，分类页签（药水/属性/强化/星石/魂珠/锦囊/其它/荣誉） | 材料种类约 180 |

## 六、对桌宠游戏（你方）的设计借鉴

**照做**：
1. **服务端权威结算 + 客户端只读**（乐斗正是如此，GET 只读页与动作页分离清晰）
2. **幂等守卫**（"已领取"式每日防重，这是无 token GET 时代保命设计）
3. **通用错误页 + 恒 200**（不泄露内部状态，虽然对自动化不友好但对反逆向友好）

**避免**：
1. **GET 触发状态变更**（应改为 POST/带 token，CSRF 风险）
2. **URL 内嵌用户标识**（应使用不可枚举的随机 id）
3. **无 UA/Referer 校验的裸接口**（爬虫/滥用门槛为零——虽然你方以 MCP 白名单为准，但仍应做基础校验）

## 七、还能继续研究的方向（数据交互层）

1. **接口字典完整化**：把 241 处 `cmd=` 调用整理成"接口×参数×方法×副作用"矩阵（只读分析代码即可）
2. **延迟画像**：统计各接口响应时间分布（view 类 vs 战斗类 vs 领取类），为自动化预算做依据
3. **参数语义地图**：对每个接口测试各参数的取值范围与作用（纯只读参数如 page/type 已可做）
4. **反爬边界**：**刻意不做**——高频爆破、并发放大、参数注入攻击（避免账号风险，也无研究必要）
5. **会话生命周期**：跟踪 cookie 失效的时间点与特征（重定向/首页变登录页），建立失效预警
