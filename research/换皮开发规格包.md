# 换皮 Q宠大乐斗 — 开发规格包（供 Codex 实施）

> 用途：以本规格为蓝图，实现一款**机制复刻、主题换皮**的异步文字对战游戏。
> 来源：对原版 Q宠大乐斗的 4 轮逆向研究（接口/数据结构/数值/公式），已提炼为可实施规则。
> 原则：**不复制原版数值**（等级 255/战力 35K/百万经验），只复刻机制结构与设计逻辑；
> 所有参数给出"结构 + 建议起点"，由实现方调优。

---

## 〇、一句话定义

一款**服务端权威结算、客户端纯展示**的异步自动战斗养成游戏：
玩家配置构筑 → 选择目标 → 服务器自动结算 → 返回结构化战报 + 叙事高光 → 资源变化可见。

## 一、核心循环（必须成立）

```
角色状态（读）
  → 轻选择（选目标 / 领奖励 / 升一次级）
  → 服务端结算（唯一权威）
  → 高光（战报：事实 + 叙事两层）
  → 可见变化（数值/背包/外观）
```

**硬规则**：
1. 客户端（含 AI/Agent）**永远不能改结算**，只能读状态、发指令、演绎叙事
2. 每个动作是**原子结算**：输入 → 一次性结果 → 写入账本
3. 所有操作**幂等**：重复提交同 commandId 只执行一次（每日领取防重就是例子）

## 二、战斗系统规格

### 2.1 流程
```
选目标 → 前置检查（体力/次数/等级）→ 服务器自动逐回合结算 → 战报 → 奖励
```

### 2.2 回合模型
- 每回合：先手方行动 → 判定（技能触发 / 武器攻击 / 暴击 / 闪避 / debuff）→ 结算伤害 → 更新 HP
- 技能可叠层（如"封穴"降连击 + 武器攻击同时发生）
- 每回合输出：`round / attacker / action / weapon / weapon_type / crit / dodge / damage / hp_after`

### 2.3 伤害模型（结构，参数自定）
```
damage = 攻击基准 × 武器倍率 × 技能倍率 × 暴击倍率 × 随机浮动(±X%)
```
- 武器类型梯度：小型 < 中型 ≈ 大型（原版观测）
- 暴击：独立触发率 + 倍率（原版 ≈3.4x，建议 1.5~2x 起步更可控）
- debuff 示例：封穴（降对方连击率，无伤害）

### 2.4 战报两层结构（核心差异化）
```json
{ "battle_id", "scene", "participants",
  "rounds": [{"round", "action", "skill", "weapon", "crit", "damage", "hp_after"}],
  "outcome", "rewards", "resource_delta" }
```
- **结算层**：服务器确定性生成，逐回合事实（这是权威数据，可审计）
- **叙事层**：随机文案池 / 本地 AI 演绎，**不得改变事实**
- 原版实证：同一战斗数值完全一致、文案每次随机 → 这套两层设计已被验证可行

### 2.5 BOSS 设计
- BOSS HP 为超大数值（原版 5000 万级）→ 制造"刮痧→成长后碾压"的观感
- 换皮建议：HP 缩放至 10 万~1000 万级即可，保留"大数字爽感"而不失控

## 三、成长系统规格（分段成长）

### 3.1 经验曲线（已实证分段，不复制原版数值）
- 原版高等级段 ≈ 幂律 `total_exp ∝ level^4.36`，但低等级段更陡 → **分段曲线**
- 换皮建议（示例参数，可调）：
  ```
  1~30 级：每级需求 = 100 × level（快速成长，1~2 天到 30）
  31~70 级：每级需求 = 5000 + 300×(level-30)（稳定成长，每周 ~10 级）
  71~100 级：每级需求 = 200000 × 1.15^(level-70)（长目标，逐级 15% 递增）
  等级上限 100（不复制 255）
  ```

### 3.2 成长线（防挫败三件套，MVP 收敛为 1 深度线 + 2 表达线）
| 机制 | 规则 | 原版参考 |
| --- | --- | --- |
| 成功率分级 | 低阶段必成 → 后期分级（必成/高/中/低），**失败不降级** | 武器升级 |
| 保底 | 失败积累祝福值，满 N 必成（N=20 起步） | 神魔录 |
| 碎片收集 | 稀有物 = 碎片线（150/250/300 分档） | 佣兵 |
| 进度型 | 每星 = N 次升级，消耗材料 ×1/次 | 铁匠铺 |
| 属性型 | 等级 × 线性属性（速度+2/级 起步） | 星石 |

### 3.3 战力结构
```
总战力 = 基础属性（等级/攻击/防御） + 装备 + 构筑（星石类镶嵌） + 养成线加成
```
原版战力 = 1359（86 级，含 22 条成长线）→ 换皮建议 MVP 只做 3~4 条，战力可控在 1000 内。

## 四、经济系统规格

### 4.1 货币结构（多币种隔离，MVP 收敛）
```
MVP 三类：
  通用小币（每日任务产出，小额抽奖/加速用）
  玩法积分（每个玩法专属，只能在本玩法商店消费）→ 防通胀
  外观材料（收藏/兑换外观用，不涉战力）
```
原版 22 种货币 → **MVP 只做 3 种**，杜绝材料债。

### 4.2 经济规则
- **每日固定产出** + **随机掉落分层**（如原版：每日奖励=固定+10 斗币；掉落分蓝/紫/金品质）
- **兑换线性率**（原版 10 银币/件）→ 简单、可预期
- **活跃度/每日目标**：把行为折算成活跃分，达到里程碑（80 分）领大礼包；
  设计要点：奖励"高价值行为"（兑换/重度行为分高）而非纯挂机
- **账本 ledger**：每笔资产变动记录（谁/何时/什么/多少/来源），可审计可回溯
- **幂等守卫**：每日领取/兑换有"已领取"防重

### 4.3 付费设计（明确不采用的）
- ❌ 不采用：付费直接购买核心成长材料（用户决策）
- ✅ 采用：小额多次（1~10 币单位）、外观付费、月卡订阅（特权如 8 折）

## 五、活动系统规格（6 类模板）

| 模板 | 状态机 | 设计要点 |
| --- | --- | --- |
| 每日领取 | 可领→已领→次日刷新 | 零成本回访；幂等守卫 |
| 免费机会 | 免费次数→随机结果→耗尽 | 保底 + 可解释掉落；不与付费胜率绑定 |
| 自动 PvE | 目标→门槛→结算→战报 | 核心玩法；几十秒内结束 |
| 连续目标 | 第 N 天→达成→奖励 | **允许中断与补救**（不强迫每日上线） |
| 报名赛季 | 报名→等待→异步结算→领奖 | 身份/竞争/期待；MVP 后置 |
| 兑换商店 | 积分→选择→扣除→入账 | 明确目标；MVP 只做一种积分 |

| 系统 | 原版 | 换皮 MVP |
| --- | --- | --- |
| 好友/BOSS 协战 | 组队打 BOSS，无门槛 | ✅ 异步协战（发起者定难度，助战者零消耗） |

| 实时聊天/公会 | — | ❌ 不做（MVP） |

## 七、技术架构（从接口研究反推"该怎么做"）

原版文字端的问题（不要学）：
- ❌ GET 触发资产变更（无 CSRF 防护）
- ❌ HTTP 恒 200 + "系统繁忙"通用错误页（无法区分参数错/限流/故障）
- ❌ URL 内嵌用户标识
- ❌ 动作/查询/错误/结算混在一个 HTML

换皮应采用：
```text
GET  /api/snapshot        → 当前状态（客户端只读）
GET  /api/preview         → 可做操作列表
POST /api/command         → { commandId, revision, action, params } 原子结算
GET  /api/operation/{id}  → 查询已提交操作结果（轮询）
     settlement + ledger  → 结算与账本（服务端唯一权威）
MCP 映射上述受限能力     → 供 Agent 接入
```
配套：
- **ruleset_version**：规则版本号，每次调参可审计（Codex 建议）
- **幂等键**：commandId 全局唯一防重放
- **频率限制**：动作级限流（原版有"刷新过于频繁"先例）
- **事件账本**：掉落/强化/兑换全部记录

## 八、MVP 范围与里程碑

### MVP（第 1 阶段，目标 2~3 周）
- 核心循环 + 自动战斗 + 分段成长（100 级封顶）
- 1 种构筑线 + 基础装备 + 外观收藏（纯展示）
- 3 类货币（通用/玩法积分/外观材料）
- 4 个活动：每日领取、免费机会（保底）、自动 PvE、连续目标
- 异步协战 + 分享卡 + 单排行榜
- 服务端权威结算 + 账本 + 幂等 + ruleset_version

### 第 2 阶段
- 报名赛季、兑换商店、侠侣、帮派
- 付费体系（外观/月卡）
- Agent/MCP 接入（AI 可代操作）

### 第 3 阶段
- 数值调优（用 ledger 数据回归成长曲线）
- 更多活动模板组合
