# 第二轮：原创桌宠的分段成长、伤害采集与经济闭环建议

日期：2026-08-21  
范围：审查本地 Q宠大乐斗研究资产，并将其**方法**转化为原创、轻量、等待 AI 间隙可玩的桌宠游戏建议。  
边界：不调用任何游戏接口，不执行游戏操作；不复用原作 IP、数值、付费逻辑或内容。

## 结论先行

1. `0.0036 × level^4.363` 只是在等级 236–255 的 **Top10 累计经验显示值** 上的经验拟合；它可描述该小样本的局部平滑关系，不能被命名为“完整经验曲线”。
2. 用它预测 86 级的“本级升级需求”后得出 -57%，存在**量纲不一致**：前者是累计经验、后者是单级所需经验。因此“低等级段更陡”目前是设计假设，不是由这次交叉验证证明的事实。
3. 原创项目仍应采用分段成长，但理由是产品体验：早期要频繁出现“我变强了”，中后期要形成可追逐的长期收藏/成长目标；不是为了拟合原作 255 级上限。
4. 当前 9 条命中记录足够验证解析管道，不足以估计暴击、武器、技能或随机浮动。并且至少两条记录的攻击者与武器文字似乎不一致，说明先要做行级数据质量门禁。
5. MVP 经济建议只保留三种功能币加一个不可消费进度条：不做付费买成长材料、不做日常税、不做材料债。

## 一、第一档分析的审查

### 1.1 可保留的结论

| 结论 | 审查结果 | 正确使用方式 |
|---|---|---|
| 高等级 10 点的幂律拟合误差约 0.4% | 成立，但仅限样本内描述 | 作为“高端长期养成通常是平滑、凸增”的观察，不外推。 |
| 商店 86 件商品中大量低价位商品 | 成立，属当前页面样本 | 可研究小额多次购买的结构；不能导出本项目定价。 |

| 命中级数据管道已建立 | 成立 | 继续只归档自然发生的战报，优先提高字段质量而非追求条数。 |
| 多玩法专属积分能隔离通胀 | 结构上合理 | 后期再考虑；MVP 先控制货币种类。 |

### 1.2 必须降级或修正的结论

| 原表述 | 问题 | 修正后的表述 |
|---|---|---|
| “F7 从不可拟合升级为经验曲线 4.363” | Top10 是不同玩家、不同等级、可能含同级内进度的累计显示，不能直接视为每级阈值。 | 已得到一个高等级排行榜显示值的局部拟合，尚未得到升级需求曲线。 |
| “86 级交叉验证 -57%，证明低等级更陡” | 累计经验与单级需求不是同一个目标变量。 | 86 级数据与拟合目标不一致；需要收集同定义数据后再判断是否分段。 |
| “战力/财富差距是数值膨胀上限” | 榜单只显示顶端，受版本、投入、留存和货币供给共同影响。 | 它说明原作存在很宽的长期差距，不提供原创项目的数值上限。 |
| “每日三条战报即可 30 天完成回归” | 三条战报不等于同构筑的有效暴击/非暴击样本；来源、装备、敌人不同会稀释样本。 | 三条归档可加快资料积累，但只按合格分层样本计数。 |

### 1.3 经验曲线的正确采集

要估计“本级升级需求”，每行必须都是同一量纲：

`level, required_exp_for_next_level, current_exp, captured_at, source, ruleset_version`

可接受来源是升级后角色页或不同等级账号的升级需求字段；不应用排行榜累计经验替代。至少覆盖 8 个等级点才比较候选曲线，12 个以上才用于设计参考。若只收集到累计经验，则应以相邻**同一规则下的等级阈值**求差分后，才得到单级需求的近似值；不同玩家的同级当前进度不能直接当阈值。

## 二、原创桌宠：分段成长曲线的参数化方案

以下不是正式数值表，而是一组能根据试玩数据调整的参数。建议把它应用于“研习等级”或“武器熟练度”，而不是堆到 255 级。

### 2.1 三段、30 级的体验目标

| 段位 | 等级 | 玩家感受 | 目标行动数 / 升级 | 主要解锁 |
|---|---:|---|---:|---|
| 发现期 | 1–8 | 每次等待间隙都看得到变化 | 1–2 次短委托 | 基础剧情、首件外观方向、第一项技能选择 |
| 成形期 | 9–20 | 能看见偏好的培养路线 | 3–5 次短委托 | 委托变体、外观制作配方、成长分支 |
| 深化期 | 21–30 | 有长期目标但不要求每日上线 | 6–10 次短委托 | 章节结局、稀有外观、称号/展示位 |

这里的“行动数”不是日上限，不与真实时间绑定。玩家关闭游戏、AI 完成或中断都不损失进度。

### 2.2 可调公式

令 `L` 为当前研习等级，`need(L)` 为升到下一等级所需学识；系数应配置在规则表而不是写死在客户端。

```text
发现期（1 ≤ L ≤ 8）:    need(L) = ceil(1.5 + 0.7 × (L - 1))
成形期（9 ≤ L ≤ 20）:   need(L) = ceil(7 + 1.5 × (L - 9))
深化期（21 ≤ L ≤ 30）:  need(L) = ceil(28 + 3.0 × (L - 21))
```

若一次安稳委托产出 1 学识、试炼产出 2、冒险产出 3，则它自然形成“风险更高、进度更快”，同时保留稳定路线。首轮试玩只需调四个旋钮：三段边界、每段截距、每段斜率、三种委托的学识产出。

### 2.3 连续性与防膨胀规则

- 段间跳变不得超过前一等级成本的 1.5 倍；否则玩家会感到突然被卡住。
- 每 3–4 级给一次**能力或展示解锁**，不只加一个攻击数字。
- 攻击或其他战斗属性优先做低幅、可预期增益；成长等级主要承担解锁和收藏节奏，避免数值互乘失控。
- 达到 30 级后转为“熟练度章节”或外观精修，不继续无限抬高基础属性。

### 2.4 需要记录的原创试玩指标

不读取用户 AI 对话或 Token。只记录本地、可关闭的游戏事件：

`行动类型、结算、获得学识、当前等级、升级耗时（行动数，不是分钟）、是否立即再次选择、是否主动退出`

成功标准不是在线时长，而是：玩家完成一次动作后能说出下一个想要追逐的目标。

## 三、同构筑伤害分层回归：数据规范与门槛

### 3.1 最小有效命中行

```text
event_id, battle_id, captured_at, parser_version, ruleset_version,
mode, scene_id, opponent_id, opponent_level_or_unknown, opponent_defense_or_unknown,
actor_side, actor_level, actor_attack, build_hash,
weapon_id, weapon_level, weapon_type, skill_id, skill_level,
crit, dodge, combo_index, buffs, debuffs,
damage, target_hp_before_or_unknown, target_hp_after_or_unknown,
raw_evidence_hash, parse_confidence
```

规则：`actor_side = player`、`damage` 为正数、非闪避、同一 `build_hash` 且解析置信度合格，才算可用于伤害研究。攻击者/武器/技能文字彼此矛盾或字段缺失的行仅用于改进解析器，不进入模型。

### 3.2 两阶段估计

**阶段 A：严格分层，先不做大回归。**

分层键：

`mode + opponent_id + build_hash + weapon_id + weapon_level + skill_id + skill_level + buffs + debuffs`

在同层内分别收集暴击与非暴击。估计值使用中位数比值：

`crit_multiplier = median(crit_damage) / median(normal_damage)`

每层最低门槛：暴击 30 条、非暴击 30 条。报告中同时给出样本数、四分位距和 bootstrap 95% 区间；未达门槛只显示观察数。

**阶段 B：探索性多因素模型。**

当合格命中达到至少 200 条，且任何准备对外比较的类别都有 ≥30 条时，才拟合：

`log(damage) = β0 + βcrit + βweapon + βskill + βstate + βopponent + ε`

敌方防御不可见时，必须把 `opponent_id` 当固定效应；不同模式不能混在同一模型中。结果只称为“观察关联”，除非规则文案或受控实验支持因果解释。

### 3.3 采集门槛与质量门禁

| 目标 | 合格数据门槛 | 不合格情形 |
|---|---|---|
| 解析器验收 | 20 条带原始证据的手工核对行 | 攻击者/伤害归属错位、空伤害被当 0 |
| 单一暴击倍率 | 同层 30 暴击 + 30 非暴击 | 混合武器、技能、敌人或状态 |
| 伤害随机浮动 | 同层、同 crit 状态至少 50 条 | 被连击、增益或敌人切换污染 |
| 初步多因素回归 | ≥200 合格行 | 类别稀疏、未知字段被强行补齐 |

“每日三条归档”可以继续，但只归档自然发生、已经完成的战报；不为满足门槛额外打任何玩法。

## 四、原创桌宠的经济闭环

### 4.1 MVP 的最小货币表

| 名称 | 类型 | 来源 | 唯一主要去向 | 是否可交易/付费购买 |
|---|---|---|---|---|
| 微光 | 通用软币 | 各类委托 | 武器强化、少量便利性重置 | 否 / 否 |
| 学识 | 绑定成长币 | 成功委托、章节奖励 | 研习等级或攻击学习 | 否 / 否 |
| 造型券 | 绑定收藏凭证 | 每 5 条线索、章节里程碑 | **指定**制作一件外观 | 否 / 否 |
| 线索 | 不可消费进度条 | 成功委托 | 解锁剧情与造型券门槛 | 不适用 |

这保留了当前本地文本原型的优点：玩家一眼看得懂“为什么获得、拿去做什么”。它有意不采用原作 22 种货币、活跃度日税、付费鹅币或成长材料直购。

### 4.2 闭环约束

1. **一源一义**：每种资源只服务一个核心决策，避免玩家不知道材料该留给谁。
2. **每次行动至少推进一件事**：即使高风险委托失败，也不扣已有资源；安稳路线永远能稳定推进线索。
3. **不制造材料债**：任何成长升级只消耗一种成长币；不要求“金币 + 三种掉落 + 周限定积分”同时齐全。
4. **外观不做战力门票**：造型券的产出与选择应确定；稀有感来自章节、收集完成度与展示，而非无底抽取。
5. **后续商业化边界**：若未来加入付费，优先是纯外观、展示页或舒适功能；不出售学识、微光、强化材料、战斗次数或暴击概率。

### 4.3 经济仪表盘（本地试玩版）

每种资源每周只检查四个聚合数：`获得量、消耗量、期末余额、中位数达成目标所需行动数`。

建议报警阈值：

- 任一必需币连续两周“消耗量 < 获得量的 30%”：说明没有吸引力的消耗点。
- 任一成长目标的中位达成成本 > 10 次短委托：说明等待间隙里目标太远。
- 两种以上资源同时阻塞同一成长动作：说明出现材料债，应删币或合并消耗。
- 造型券余额长期为 0 且玩家已收齐可做外观：增加新外观内容，不提高券产出。

## 五、下一步（只读研究与原创实现的分界）

### 研究可做

- 收集同量纲的 `level → required_exp` 记录，先报告表格再拟合。
- 对命中行执行字段完整性、攻击者归属和重复事件检查。
- 继续归档自然发生的战报，按同构筑层统计进度。

### 原创桌宠下一步可实现

- 把当前“学识 → 攻击”的线性成本替换为配置化三段 `need(L)` 表，并记录规则版本。
- 在状态里显示“到下一等级还需几次安稳/试炼委托”的**范围**，不承诺随机战斗必胜。
- 保持现有“线索 → 造型券 → 指定外观”确定性收藏线；先由创始人试玩感受决定是否增加第二条成长分支。

### 明确不做

- 不按 255 级、35K 战力、百万经验或 22 货币体系缩小复刻。
- 不把排行榜、榜首账户、价格表当原创项目的平衡目标。
- 不为研究触发战斗、抽取、强化或任何会消耗账号资源的行为。

## 六、DSH → Codex 的研究交接接口（2026-08-21）

协作对象是原创 AI 等待间隙桌宠项目，不是 Q宠大乐斗换皮或机制复刻项目。DSH 的职责是脱敏资料研究、数据质量与机制结构分析；Codex 的职责是产品范围、原创规则、代码、测试与试玩。研究文件不得包含账号、Cookie、原始页面快照、请求参数或可操作第三方接口信息。

每个可交给 Codex 的研究结论使用下列格式：

```text
研究问题：
来源范围与日期：
观察量 / 样本门槛：
证据等级（页面显示 / 多源印证 / 代码注释 / 推断）：
可复用的抽象结构：
不可迁移内容（IP、现行数值、付费、时段/日常强迫等）：
待验证项：
建议映射到原创规则表的字段：
```

当前优先研究任务：

1. 审计命中行解析质量，给出合格率、错位类型和字段补全建议；不输出伤害倍率。
2. 从活动模板中抽取“短行动 / 安稳推进 / 章节里程碑 / 收藏目标”的结构，筛除日常税、固定时段和连续登录压力。
3. 用账本视角验证“每种资源一个主要去向”的闭环，而不是增加货币种类。
4. 为未来异步协战研究“冻结快照、双方零消耗/独立奖励、一次性幂等结算”的数据契约；不研究实时聊天、公会或第三方接口自动化。
