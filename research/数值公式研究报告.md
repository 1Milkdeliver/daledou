### 1.4 战斗结构算法（★ 已确认）

```
回合循环:
  while HP > 0 and 回合 < 上限:

    更新 HP
  输出: 结算 + 叙事包装（随机文案，不影响数值）
```

## 五·b、经验曲线与设计约束（2026-08-21 用户决策）

**拟合结论（高等级段）**：`total_exp ≈ 0.004 × level^4.363`（236~255 级，误差 0.4%），
但 86 级交叉验证 -57% → **单一公式不能覆盖全程，经验曲线为分段形状**（低等级段更陡）。

**设计决策（用于桌宠 MVP，不照搬原作）**：
1. ✅ 采用**分段成长**：早期频繁成长（短目标、快速反馈），后期长目标化（里程碑式）
2. ✅ 成长曲线形状参考（幂律结构），但**不复制 255 级 / 百万级经验数值**
3. ✅ 同构筑命中分层采样（战报管道），**只归档已发生战斗、绝不触发额外战斗**
4. ✅ 多货币/材料闭环结构研究（经济设计参考）
5. ❌ 不采用：付费直接购买核心成长材料
6. ❌ 不采用：用全服天花板数值（战力 35K/斗豆 6.7M）倒推小体量桌宠
7. ❌ 不采用：为采样引入日常强制行为

## 五·c、命中行解析质量审计（DSH 交接 · 任务1，2026-08-21）

> 研究问题：`battle_hits.py` 产出的命中级数据质量如何？字段缺失、攻击者/武器错位、
> 合格率各是多少？如何修复？——本项**不输出伤害倍率**（倍率结论需合格样本后另行处理）。

**来源范围与日期**：log/hits_dataset.json（2026-08-20 归档战报），log/hit_quality_audit.json。
**观察量**：1 场战报 / 9 条命中（样本量极小，仅用于管道验证，不做统计推断）。

**证据等级**：页面显示（战报原文对照解析输出）。

| 审计项 | 结果 | 问题类型 |
| --- | --- | --- |
| damage 覆盖率 | 7/9（78%） | 对手回合/闪避回合无伤害值属正常，非缺失 |
| hp_after 覆盖率 | 7/9（78%） | 同上 |
| weapon 覆盖率 | 5/9（56%） | 攻击者非玩家或非武器回合不计 |
| **武器名污染** | **4/9（44%）** | 叙事前缀混入：`忽然土豪金`/`把真·金砖`/`把五雷轰顶`/`轮起狂魔镰` |
| **行动类型错位** | 2 条 action=「暴击」 | 暴击是修饰符不是行动；应归并到 crit 标志 |
| 攻击者判定 | 0 错位 | 玩家/对手判定正确（对手回合闪避无伤害） |
| 闪避/暴击标志 | 二元标志正常 | crit 5 条、dodge 0 条（非 0% 缺失，是二元布尔） |

**可复用抽象结构**：
1. 战报解析应**先剥离叙事前缀**（忽然/把/摸出/轮起/使起…）再做字段提取；
   或维护武器名词典，在叙事中定位武器名后用"词典匹配"而非通用正则
2. `crit/dodge` 设计为**二元标志**（解析时默认 False，命中才置 True）——这比"缺失"更可审计
3. 行动类型采用**白名单**（普攻/技能名/debuff 名），解析器只在白名单内赋值，杜绝"暴击"混入

**不可迁移内容**：原版武器名/技能名/叙事文案（换皮不复制）；伤害数值与倍率（本项不输出）。

**待验证项**：
- 多个战报源（历练/斗神塔/好友）各 10+ 条后重新统计合格率
- 武器名词典方案 vs 前缀剥离方案，哪个合格率更高
- 对手回合（attacker=opponent）的字段完整度单独统计

**建议规则表字段**（命中行，原创项目用）：
```text
hit_id / battle_id / ruleset_version / round_no / attacker_role(player|npc)
action_type(enum: normal|skill|debuff) / skill_id / weapon_id / weapon_tier
crit(bool) / dodge(bool) / damage / hp_after / target_id / raw_narration_hash
```
